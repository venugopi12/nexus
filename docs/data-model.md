# Data model (PostgreSQL, Drizzle)

Migrations live in `apps/api/drizzle/` (generated by `drizzle-kit generate`, applied by `pnpm db:migrate` and on API start).
Schema source: `apps/api/src/db/schema.ts`.

```
organizations ─┬─< memberships >─ users ─< sessions
               ├─< services ─< service_deps (from,to)
               │      └─< faults            (simulator ground truth; never exposed to the assistant)
               ├─< events   (id = deterministic hash)       ├─< deployments
               ├─< traces ─< spans                           ├─< alert_rules ─< alerts ── incident?
               ├─< incidents ─< incident_services / _responders / _timeline / _links
               ├─< notifications (per user)                  ├─< audit_logs
               └─< flag_overrides >─ feature_flags ─ flag_history
```

| Table | Notes |
|---|---|
| `organizations` | tenant; `settings` JSON (timezone, retention, default env) |
| `users`, `memberships` | one user may belong to several orgs with a **per-org role** (`admin/sre/engineer/viewer`) |
| `sessions` | `token_hash` = SHA-256 of a 256-bit random token (the raw token only exists in the cookie); `org_id` = active org |
| `services` | per-org; `config` JSON keyed by environment; unique `(org_id, key)` |
| `service_deps` | directed edge caller → callee |
| `faults` | simulator input: kind, magnitude, start/end, `chaos_key` unique for idempotent injection |
| `events` | ≈ 108k seeded; index `(org_id, environment, ts desc)`; `id` is deterministic so inserts are idempotent |
| `traces`, `spans` | seeded; span offsets/durations are consistent with parent/child nesting |
| `incidents` | per-org sequential `number` (advisory lock), `version` for optimistic concurrency, `acknowledged_at` / `resolved_at` for TTA/TTR |
| `incident_timeline` | append-only activity feed (status/severity/owner/comment/note/link/alert) |
| `incident_links` | event / trace / deployment evidence; targets validated to belong to the same org |
| `alert_rules`, `alerts` | partial unique index `alerts_one_open (rule_id, coalesce(service_id, nil-uuid)) WHERE status <> 'resolved'` guarantees one open alert per rule+service |
| `audit_logs` | actor, action (`incident.resolved`, `member.role_changed`, …), resource, metadata |
| `feature_flags`, `flag_overrides`, `flag_history` | global default → org override → environment override; history is audit trail |

Indexes follow the access paths: incidents by `(org, status, created desc)`, events by `(org, env, ts desc)` and `(service, ts desc)`,
audit by `(org, at desc)`, notifications by `(user, org, created desc)`.
